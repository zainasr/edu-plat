# Frontend (web staff portal)

Status: planned. Nothing is scaffolded yet. The stack is decided in `docs/adr/0016-web-stack.md`; the first web slice is planned with `/plan-slice`.

## Stack
Next.js, strict TypeScript, Tailwind CSS, shadcn/ui (components copied into `apps/web/components/ui`), `openapi-typescript` + `openapi-fetch`, Vitest + Testing Library, Playwright + axe.

## Rules
- The API contract is the source of truth. Types come from `api/openapi/openapi.yaml`, generated by `make gen` into a `gen/` folder that is never hand-edited. CI fails if generated files are stale.
- **Sign-in and the token.** The browser never holds a bearer token. Next.js route handlers call the OTP endpoints, store the session token in an httpOnly, Secure, SameSite=Lax cookie, and attach it to API calls made from the server. Client components call our own route handlers, not the Go API directly.
- Money arrives as `{amount, currency}` with integer paisa. Format it in one helper; never use floating point arithmetic on it.
- All UI text is English, in one messages file; no hard-coded product name.
- Permissions: hide or disable what the user cannot do, but the API is the enforcement; handle 401 (re-sign-in) and 403 (message) everywhere.
- Accessibility: labelled inputs, keyboard operation, visible focus; axe must be clean in Playwright.
- Dependencies: ask the owner and write an ADR.

## Folder layout (target)
```
apps/web/
  app/            routes, layouts, route handlers (BFF)
  components/ui/  shadcn components
  features/<module>/  screens, forms, hooks for one spec module
  lib/api/        generated types and the fetch client
  lib/messages.ts UI strings
  tests/          Vitest; e2e/ for Playwright
```

## Slice recipe
`/dev-context` → `/plan-slice` (screens, API endpoints used, permissions, empty/error states) → owner approves → `/frontend-slice` (types from `make gen`, tests first, screens) → `/verify` → `/ship`.

## Definition of done
Typecheck, lint, unit tests, Playwright happy path and error path against the real API and database, axe clean, generated client current, requirement IDs listed, no secrets, small commits, push only with the owner's yes.
