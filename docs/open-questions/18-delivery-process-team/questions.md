# 18 Delivery process, governance and timeline

1. (BLOCKER) Target dates: pilot start, public 1.0 launch, 1.1, 1.2. Hard deadlines (admission season is Mar-Apr/ Aug-Sep in Pakistan; session start)?
2. Which SDLC model do we run: phased gates (requirements -> design -> validation -> planning -> build -> test -> release) with agile sprints inside the build phase? Gate criteria and sign-offs by whom?
3. Stakeholders who must approve the SRS (pilot school owners, accountant, teacher, parent representatives, legal)? How do we collect their feedback (workshops, prototype tests)?
4. Prototype/validation: do we build clickable Figma prototypes for key flows to validate with schools before development?
5. Product ownership: who decides scope changes? Change-control process after SRS freeze?
6. Estimation and planning: epics -> stories -> sprint length (1 or 2 weeks), velocity tracking, tooling (Jira/Linear/GitHub Projects)?
7. Definition of Ready and Done (acceptance criteria, tests, docs, security review, performance check)?
8. Quality gates: UAT with pilot schools, bug severity policy, release criteria (zero critical/high bugs), beta program?
9. Release management: app store accounts, versioning, release trains (weekly web, bi-weekly mobile), rollback.
10. Risk register: top risks (payment integration delays, WhatsApp approvals, offline sync complexity, data quality, adoption, funding). Mitigation owners?
11. Budget and runway assumptions affecting scope.
12. Documentation deliverables: SRS, architecture docs, API docs, user manuals, admin guides, runbooks, onboarding guides, privacy docs. Which are needed before pilot?
13. Metrics for process: lead time, deployment frequency, defect escape rate, NPS from pilots.
14. Legal/entity: company registration, SECP, NTN, bank account, trademarks, app store developer accounts, domain names — status and owners?
